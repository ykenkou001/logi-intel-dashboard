## 1. このダッシュボードでできること

Logi-Intel Dashboard は、CLO（物流統括管理者）が中長期計画を作り、社内に説明し、提出後の運用を続けるための支援ツールです。

単にグラフを見るためのダッシュボードではありません。次の 5 つの作業を一つの流れで進められるように作られています。

| 作業 | 何をするか | 主に使う画面 |
|------|------------|--------------|
| 1. 自社データを準備する | Excel テンプレートを取得し、拠点・荷待ち・荷役・KPI を登録する | 自社プロフィール入力 |
| 2. 外部環境を把握する | 都道府県、業界、ドライバー不足などの外部データを見る | マクロ概況、業界ベンチマーク、ドライバーギャップ |
| 3. 改善施策を選ぶ | 標準施策を検索し、自社に合う Top 3 候補と不採用理由を確認する | 施策プレイブック、施策評価、シナリオ試算 |
| 4. CLO 計画書を作る | 社内説明資料、提出様式ドラフト、Excel 明細、HTML を出力する | 計画書生成 |
| 5. 提出後に運用する | 今日判断すべきこと、標準からのズレ、効果が出ていない施策、荷待ちリスクを追う | デイリーコックピット、F2 標準化スコア、J2 罠スコア、荷待ちヒートマップ |

はじめて触る場合は、全画面を順番に見る必要はありません。まずは「自社プロフィール入力」「業種別パッケージ」「F2 標準化スコア」「J2 罠スコア」「施策評価」「計画書生成」の 6 画面だけで全体像を掴めます。

画面上部のヘッダーには、よく使う 9 画面（ガイド／コックピット／業種別パッケージ／標準化スコア／罠スコア／施策評価／シナリオ／計画書生成／自社情報）へのグローバルナビが常時表示されているので、迷ったらそこから戻れます。

## 2. 最初に見るべき順番

### 2.1 社内で短時間に説明したい場合

5 分から 10 分で概要を見せるなら、次の順番が最も伝わりやすいです。ホーム画面に固定表示されている「業種別デモ動線」と同じ流れです。

| 順番 | 画面 | 見せるポイント |
|------|------|----------------|
| 1 | ホーム | どんな機能群があるかを一覧で見せる |
| 2 | 業種別 CLO 標準パッケージ | 製造・卸・小売・連鎖化で見るべき KPI や施策が違うことを見せる |
| 3 | F2 標準化スコア | 自社が標準からどこだけ外れているかを見せる |
| 4 | J2 罠スコア | 投資したのに効いていない施策を客観的に検出できることを見せる |
| 5 | デイリーコックピット | 「今日の3判断」が朝1回で完結することを見せる |
| 6 | 計画書生成 | PPT / Word / Excel / HTML / Markdown が出ることを見せる |

この順番にすると、「分析できる」「運用できる」「社内説明資料まで出せる」の 3 点が一度に伝わります。

### 2.2 CLO 担当者が実務で使う場合

実務では、まず自社データを入れてから分析するのが自然です。

| 順番 | 画面 | やること |
|------|------|----------|
| 1 | 自社プロフィール入力 | Excel テンプレートをダウンロードし、自社データをアップロードする |
| 2 | 業種別 CLO 標準パッケージ | 自社がどの業種標準に当たるか確認する |
| 3 | F2 標準化スコア | 足りない KPI と未採用施策を確認する |
| 4 | J2 罠スコア | 既に実行中の施策のうち「効いていない」ものを確認する |
| 5 | 荷待ちヒートマップ | 拠点別・時間帯別に待機リスクを見る |
| 6 | 施策評価 | 優先施策 Top 3 と不採用理由を確認する |
| 7 | シナリオ試算 | 施策実施後の費用対効果や上振れ・下振れを見る |
| 8 | 計画書生成 | 社内レビュー用の成果物を出す |
| 9 | デイリーコックピット | 提出後の運用で、今日判断すべき 3 件を追う |

### 2.3 営業・企画が顧客説明のたたき台を作る場合

顧客や社内提案前の仮説作りでは、実データがなくてもサンプル企業で流れを説明できます。

| 順番 | 画面 | やること |
|------|------|----------|
| 1 | ホーム | 全機能の位置づけを確認する |
| 2 | マクロ概況 | 対象都道府県の外部環境を確認する |
| 3 | 業界ベンチマーク | 業種・売上規模・物流コスト比率の目安を見る |
| 4 | 施策プレイブック | 提案候補になりそうな標準施策を探す |
| 5 | 施策評価 | サンプル企業で Top 3 推薦と不採用理由の見え方を確認する |
| 6 | 計画書生成 | どのような成果物が出るか確認する |

## 4. 各画面の詳しい説明

### 4.1 ホーム

| 項目 | 内容 |
|------|------|
| URL | `/` |
| 何をする画面か | 全機能への入口。業種別デモ動線（4 業種サンプル）と各機能カードから目的の画面に移動する |
| 初見ユーザーの使い方 | まず業種別デモ動線で対象に近いサンプル（製造／卸／小売／連鎖化）を選び、業種別パッケージから順に巡る |
| 見るべきポイント | 画面が「データ把握」「施策評価」「標準化」「罠検出」「成果物生成」「運用」に分かれていること、初回提出期限までの残日数バナー |
| 次に進む画面 | 自社データがある場合は「自社プロフィール入力」、説明デモなら「業種別 CLO 標準パッケージ」 |

ホームは、すべての画面を均等に使うためのメニューではありません。ユーザーの目的に応じて、最短ルートを選ぶための入口です。業種別デモ動線では「業種別パッケージ → 標準化 → 罠 → コックピット → 計画書」の 5 ステップが各サンプル企業に紐付けて表示されます。

---

### 4.2 自社プロフィール入力

| 項目 | 内容 |
|------|------|
| URL | `/dashboard/company` |
| 何をする画面か | 自社の物流データを Excel テンプレートで登録し、サンプル企業ではなく実データで分析できるようにする |
| 主な入力 | テンプレート用途、アップロードする Excel ファイル |
| テンプレート用途 | `annual` 計画策定用、`monthly` 月次レビュー用、`daily` 日次運用入力用 |
| 主な出力 | Excel テンプレート、アップロード結果、永続化された `company_id` |
| 主な利用者 | CLO 担当者、企画担当者、分析担当者 |

この画面は、実務で最初に使うべき画面です。サンプル企業のままでもデモはできますが、実際の計画書や施策評価には自社データが必要です。

Excel には主に次の情報を入れます。

| シート | 何を入れるか | 使われる先 |
|--------|--------------|------------|
| `profile` | 会社名、業種、売上、物流費、貨物量、CLO 情報など | 業界ベンチマーク、適用判定、計画書生成 |
| `sites` | 拠点名、都道府県、拠点種別、年間貨物量など | 荷待ちヒートマップ、計画書、拠点別分析 |
| `wait_time` | 荷待ち時間、計測便数、時間帯や月次の集計 | 荷待ちヒートマップ、定期報告、デイリーコックピット |
| `handling_time` | 荷役等時間、計測便数、最大値など | 定期報告、法令対応、改善対象抽出 |
| `kpi_history` | 積載率、CO2、物流費率などの履歴 | F2 スコア、デイリーコックピット、進捗確認 |

結果を読むときは、「アップロードが成功したか」だけでなく、表示された `company_id` を確認してください。この ID が、計画書生成や施策評価で会社を選ぶキーになります。

### 4.3 業種別 CLO 標準パッケージ

| 項目 | 内容 |
|------|------|
| URL | `/dashboard/industry-package` |
| 何をする画面か | 自社の業種に応じて、標準的に見るべき KPI、施策、会議体、レポート、データ項目を確認する |
| 主な入力 | 会社 ID、またはサンプル企業 |
| 主な出力 | 業種ラベル、標準 KPI、標準施策、標準会議体、標準レポート、標準データ項目、Override 件数 |
| 主な利用者 | CLO 担当者、上長、企画担当者、営業 |

この画面は、初見ユーザーに最も説明しやすい画面です。「この会社の CLO 運用では、何を標準として見るべきか」を一覧で示します。

業種は大きく次の 4 種類です。

| 業種 | 何を見るか |
|------|------------|
| 製造 | 工場・出荷拠点、積載率、荷待ち、モーダルシフト、共同配送 |
| 卸売 | 倉庫・配送網、共同配送、倉庫 DX、物流コスト比率 |
| 小売 | 店舗配送、納品頻度、DC、店舗側の待機・荷役制約 |
| 連鎖化事業者 | フランチャイズ本部としての第65条対応、加盟店を含む標準運用 |

画面の見方は次の通りです。

| 表示 | 読み方 |
|------|--------|
| 標準 KPI | この業種なら最低限見ておきたい指標 |
| 標準施策 | 計画書や月次会議で検討対象に入れるべき施策 |
| 標準会議体 | CLO がどの頻度で、誰と、何を確認するか |
| 標準レポート | 月次レビューや経営会議に必要なレポート |
| 標準データ項目 | その業種で分析精度を上げるために必要な入力データ |
| Override | 標準から外れる事情を、承認済み・地域制約・法令制約・未管理などに分類したもの |

この画面で大事なのは、「標準から外れていること自体は悪ではない」という点です。合理的な個別事情なら Override として説明できます。一方、理由なく放置されているズレは、F2 標準化スコアで減点対象になります。

### 4.4 F2 標準化スコア

| 項目 | 内容 |
|------|------|
| URL | `/dashboard/standardization` |
| 何をする画面か | 自社が業種別標準パッケージにどれだけ準拠しているかを 0-100 で確認する |
| 主な入力 | 会社 ID、またはサンプル企業 |
| 主な出力 | スコア、算出根拠、未計測 KPI、未採用施策、充足・不足の差分 |
| 主な利用者 | CLO 担当者、上長、内部監査、企画担当者 |

F2 標準化スコアは、「この会社は CLO 運用の標準型にどれだけ近いか」を見る指標です。

| スコア帯 | 目安 | どう使うか |
|----------|------|------------|
| 80 以上 | 標準にかなり近い | 計画書生成や経営説明に進みやすい |
| 50 以上 80 未満 | 部分的に不足あり | 未計測 KPI と未採用施策を確認し、優先順位を付ける |
| 50 未満 | 標準運用との差が大きい | まずデータ整備と必須施策の棚卸しから始める |

画面で特に見るべき項目は次の 3 つです。

| 見る項目 | 意味 |
|----------|------|
| 未計測 KPI | 標準では見るべきなのに、自社データにまだ入っていない指標 |
| 未採用施策 | 業種標準では採用候補なのに、自社側で未採用扱いの施策 |
| rationale | なぜそのスコアになったかを説明する文章 |

上長説明では、「点数が高いか低いか」だけでなく、「何が不足しているから点数が下がっているか」を見せると伝わります。点数はゴールではなく、次に集めるデータや検討する施策を決めるための入口です。

連鎖化事業者（`sample_chain_01` 等）では、第65条の制約により荷役系（`loading`）施策を採用しても追加減点される仕様になっています。これは「FC 本部は荷役を直接管理しない」という法令前提を反映したものです。

### 4.5 J2 罠スコア

| 項目 | 内容 |
|------|------|
| URL | `/dashboard/waste-traps` |
| 何をする画面か | 既に実行中の施策のうち、投資に対して効果が出ていない「罠」を 6 軸セーフガード付きで検出する |
| 主な入力 | 会社 ID（永続化された施策実行記録 `outputs/measure_runs/<company_id>.json` を読み込む） |
| 主な出力 | 重大度別件数（重大／要注意／軽微）、罠候補一覧、推定原因、推奨対応、投資凍結推奨フラグ |
| 主な利用者 | CLO 担当者、経営企画、内部監査、財務 |

J2 罠スコアは、「やってみたが効いていない施策」を客観的に検出するための画面です。F2 標準化スコアが「標準型に対する充足度」を見るのに対し、J2 は「実行済み施策の費用対効果」を見ます。

検出ロジックは「投資額」「期待効果」「実績効果」「経過月数」を元にしますが、次の 6 軸セーフガードが発火した場合は重大度を低に固定し、誤検知を抑止します。

| セーフガード | 何を抑止するか |
|--------------|----------------|
| 立ち上げ期間 | 施策開始直後で効果がまだ出ていないだけのケース |
| データ欠損 | 実績効果が未入力で評価できないケース |
| サンプル数不足 | 計測便数や対象拠点が少なく、ばらつきが大きいケース |
| 季節性 | 繁忙期・閑散期の影響で短期的にブレているケース |
| 外部要因 | 燃料高騰・天候・取引先要因など、施策外の影響が大きいケース |
| 投資回収前 | 想定回収期間にまだ達していないケース |

画面の読み方は次の通りです。

| 表示 | 読み方 |
|------|--------|
| 重大 | 重大かつセーフガード非該当。経営会議で扱うべき罠候補 |
| 要注意 | 効果が想定より明確に低いが、撤退判断には情報不足 |
| 軽微 / 保留 | セーフガード発火または軽度の乖離。継続観察 |
| 投資凍結を推奨 | 規模不適合・KPI 設計誤り・実装品質に該当する重大罠。追加投資を止めるべき |
| 推定原因 | 規模不適合・KPI 設計誤り・実装品質・外部要因のどれに該当しそうか |
| 推奨対応 | 撤退・縮小・KPI 再設計・体制見直しなどの方向性 |

施策実行記録が永続化されていない場合は「データ未登録」として 0 件表示になります。MCP ツール `logi_clo_waste_traps` または REST `POST /api/v1/clo/waste-traps/{id}` に `measure_runs` を渡すと永続化されます。

上長説明では、「重大件数 + 投資凍結推奨件数」を最初に見せると伝わります。「年間 X 億円分の施策のうち、Y 件が回っていません」と数字で示せるからです。

### 4.6 施策プレイブック

| 項目 | 内容 |
|------|------|
| URL | `/dashboard/playbook` |
| 何をする画面か | CLO 計画書に使える標準施策を検索・絞り込みする |
| 主な入力 | 業種、最大難易度、様式第3セクション、施策タイプ |
| 主な出力 | 施策一覧、効果、難易度、対象業種、様式第3との対応 |
| 主な利用者 | CLO 担当者、営業、企画、コンサル代替の一次調査担当 |

施策プレイブックは、「どんな打ち手があるか」を探す画面です。施策評価のように自動で Top 3 を決める画面ではなく、候補施策を広く見るために使います。

主な標準施策には、次のようなものがあります。

| 施策 | 目的 |
|------|------|
| モーダルシフト | 長距離輸送を鉄道・船舶へ移し、CO2 とドライバー負荷を下げる |
| TMS 配車最適化 | 配車計画を最適化し、積載率と配送効率を上げる |
| 共同配送 | 複数社・複数拠点の配送を束ね、車両効率を上げる |
| バース予約 | 入出荷予約を整え、荷待ち時間を削減する |
| パレット標準化 | 手荷役や積み替えを減らし、荷役等時間を短縮する |
| 中継輸送 | 長距離運行を分割し、拘束時間や宿泊負担を下げる |
| WMS 導入 | 倉庫作業を可視化・標準化し、出荷品質と効率を上げる |

施策を探すときは、次のように考えると使いやすいです。

| 状況 | 絞り込み例 |
|------|------------|
| 荷待ちが課題 | 様式第3セクションを荷待ち系に寄せる |
| すぐ始めたい | 最大難易度を低めにする |
| 製造業向けに見たい | 業種を製造にする |
| 設備投資を避けたい | 難易度や投資規模が低い施策を優先して見る |

### 4.7 施策評価(Top 3 推薦 + judgment trail)

| 項目 | 内容 |
|------|------|
| URL | `/dashboard/measure-eval` |
| 何をする画面か | 自社プロフィールに基づき、優先して検討すべき改善施策 Top 3 と、推薦しなかった理由（Bottom）まで提示する |
| 主な入力 | 会社 ID、またはサンプル企業 |
| 主な出力 | 推薦施策 Top 3、不採用 Bottom、4 軸スコア、選定根拠（judgment trail） |
| 主な利用者 | CLO 担当者、上長、営業、企画 |

施策評価は、「どの施策から検討すべきか」を決めるための画面です。スコアリングは 4 軸で行い、加重合計で Top 3 を選びます。

| 軸 | 重み | 意味 |
|----|------|------|
| ROI | 35% | 投資に対してコスト削減や効果が見込めるか |
| 実装可能性 | 30% | 自社の規模、データ、現場リソースで実行できそうか |
| 法令適合 | 25% | CLO 中長期計画や様式第3に書きやすい施策か |
| 補助金 | 10% | 補助金・認定制度・支援策と相性があるか |

この画面は単に Top 3 を並べるのではなく、judgment trail（判断の足跡）として **Bottom（不採用候補）と不採用理由**も併せて表示します。経営会議で「なぜそれを選んだか」「他はなぜダメか」を即答するための作りです。

Top 3 は、すぐ実行決定すべき最終案ではありません。社内調整で優先して検討する候補です。1 位だけを見て終わらず、2 位・3 位との差を見てください。差が小さい場合は、現場負荷や社内合意のしやすさで順番が変わる可能性があります。

### 4.8 シナリオシミュレーション

| 項目 | 内容 |
|------|------|
| URL | `/dashboard/scenario-sim` |
| 何をする画面か | 施策を実行した場合の複数シナリオを比較し、財務インパクトやリスクを見る |
| 主な入力 | 会社 ID、評価対象施策 |
| 主な出力 | 保守・標準・上振れシナリオ、費用対効果、回収期間、リスク感 |
| 主な利用者 | CLO 担当者、経営企画、上長、財務・管理部門 |

シナリオシミュレーションは、施策評価の次に見る画面です。施策評価で候補を絞り、シナリオ試算で「本当に投資判断に耐えるか」を確認します。

画面の読み方は次の通りです。

| シナリオ | 読み方 |
|----------|--------|
| 保守 | 効果が小さめに出た場合でも、投資判断が成り立つかを見る |
| 標準 | 通常想定の効果。社内説明の基本線になる |
| 上振れ | 施策がうまく進んだ場合の最大効果を見る |

上長説明では、標準シナリオだけでなく保守シナリオを見せると説得力が上がります。「うまくいった場合」だけでなく、「控えめに見ても意味があるか」を説明できるからです。

### 4.9 計画書生成

| 項目 | 内容 |
|------|------|
| URL | `/dashboard/plan-draft` |
| 何をする画面か | CLO 中長期計画のドラフトと社内説明用成果物を一括生成する |
| 主な入力 | 会社 ID、またはサンプル企業 |
| 主な出力 | PowerPoint、Word、Excel、HTML、Markdown、出典情報 |
| 主な利用者 | CLO 担当者、上長、営業、企画、社内説明資料作成者 |

この画面は、ダッシュボードの出口です。分析結果を見て終わりではなく、社内でレビューできる成果物に変換します。生成には 30〜60 秒かかります。

生成される主なファイルは次の通りです（5 種類）。

| ファイル | 用途 |
|----------|------|
| PowerPoint | 経営会議、上長レビュー、関係部署説明（最優先） |
| Word | 国交省様式第3別紙の中長期計画書ドラフト・e-Gov 提出用 |
| Excel | 数値表 + 出典シート、社内確認用 |
| HTML | 詳細閲覧・印刷向け、社内ポータル掲載用 |
| Markdown | 担当者が文章をレビュー・修正しやすいテキスト版 |

ダウンロードボタンを押すとブラウザのプレビューを経由せず、即座にファイル保存ダイアログが開きます。

初見ユーザーには、最後にこの画面を見せるのが効果的です。前段の画面が「分析」だとすると、この画面は「成果物」です。上長にとっては、最終的に何が手元に残るかが重要です。

注意点として、出力は提出用の完成版ではなくドラフトです。法令提出前には、人間のレビュー、社内承認、最新様式との照合が必要です。

### 4.10 デイリーコックピット

| 項目 | 内容 |
|------|------|
| URL | `/dashboard/cockpit` |
| 何をする画面か | CLO が今日判断すべき 3 件を表示し、採用・保留・却下を I2 ログに記録する |
| 主な入力 | 会社 ID、またはサンプル企業 |
| 主な出力 | 3 軸の判断カード、緊急度、経営インパクト、自信度、想定反論、健全度バッジ、前日比、I2 意思決定ログ |
| 主な利用者 | CLO 担当者、部門長、経営企画 |

デイリーコックピットは、提出後の運用で使う画面です。すべての KPI を一覧するのではなく、CLO が今日判断すべき項目を 3 件に絞ります。

3 軸は次の通りです。

| 軸 | 意味 |
|----|------|
| 軸 A 法令・提出リスク | 放置すると法令対応や提出準備に影響するもの |
| 軸 B KPI 未達 | 積載率、荷待ち、物流費率などの未達や悪化 |
| 軸 C 今週決める施策 | 施策実行・社内合意・投資判断で止まっているもの |

各カードでは、次の情報を確認します。

| 表示 | 読み方 |
|------|--------|
| 緊急度 | 今日または今週中に動くべきか（0-100） |
| 経営インパクト | コスト、法令、現場負荷、顧客影響の大きさ（0-100） |
| 自信度 | データやロジックの確からしさ（0-100） |
| 想定反論 | 会議で出そうな反対意見（J4 薄版） |
| 滞留日数 | このカードが何日 pending のままか |
| 採用・保留・却下 | CLO の判断として I2 ログ（append-only jsonl）に記録 |

画面上部には全体の健全度バッジ（緑／黄／赤）と前日比（積載率・荷待ち平均など）が表示されます。

この画面は、日々の会議前に見るのが最も実用的です。CLO が「今日は何を判断するべきか」を絞るための画面であり、全 KPI の詳細分析画面ではありません。

### 4.10.5 KPI 月次推移

| 項目 | 内容 |
|------|------|
| URL | `/dashboard/kpi-timeseries` |
| 何をする画面か | 積載率・荷待ち時間・荷役時間・CO2 原単位・F2 標準化スコアの月次推移を可視化し、悪化を早期発見する |
| 主な入力 | 会社 ID、記録対象月（YYYY-MM） |
| 主な出力 | 24 ヶ月折れ線チャート、悪化アラート（注意/警告/重大）、月次スナップショット一覧表 |
| 主な利用者 | CLO 担当者、経営企画、月次レビュー担当 |

デイリーコックピットが「今日の 3 判断」に絞った日次ビューであるのに対し、KPI 月次推移は「計画線に乗っているか」を月次粒度で確認する画面です。月次会議や四半期レビューで使います。

データの仕組みは次の通りです。

| 由来 | 中身 |
|------|------|
| 日次データから月平均化（rolled_up_from_daily） | コックピットが当日に保存した `outputs/cockpit_snapshots/<id>/<yyyymmdd>.json` を月単位で平均化したもの |
| 手入力（manual_entry） | 日次データが無い月でも F2 標準化スコア / J2 罠件数のみを保存したもの |

「当月分のスナップショットを記録」ボタンを押すと、その月の日次データ + F2 / J2 をその場で計算して履歴に append します。記録後、24 ヶ月分が古→新で折れ線表示されます。

悪化アラートの判定ルールは次の通りです。

| 指標 | 悪化方向 | 注意（watch） | 警告（warn） | 重大（critical） |
|------|----------|----------------|---------------|-------------------|
| 積載率 | 低下 | -2pt | -5pt | -10pt または 3 ヶ月連続低下 |
| 荷待ち平均・最大 | 増加 | +10% | +25% | +50% または 3 ヶ月連続増 |
| 荷役等時間 | 増加 | +10% | +25% | +50% または 3 ヶ月連続増 |
| CO2 原単位 | 増加 | +5% | +10% | +20% または 3 ヶ月連続増 |
| 物流コスト/売上比率（v1.1）| 増加 | +15% | +30% | +50% または 3 ヶ月連続増 |
| F2 標準化スコア | 低下 | -3pt | -10pt | -20pt または連続低下 |
| J2 罠件数（high） | 増加 | +1 件 | +3 件 | +5 件 または連続増 |

基準値は「3 ヶ月前のスナップショット」（無い場合は最古スナップショット）です。「3 ヶ月連続で悪化方向」であれば閾値未満でも重大扱いに引き上げます。各悪化アラートには **基準: 3 ヶ月前比 / 最古スナップショット比** がバッジ表示されます（v1.1）。

### v1.1: 物流コスト/売上比率と業界平均

「当月の物流コスト実績（円）」を入力欄に記入してスナップショットを記録すると、年間売上 / 12 で当月推計売上を割って物流コスト比率（0-1）を計算します。未入力の場合は自社プロフィールの `kpi_history`（最新年度の `logistics_cost_revenue_ratio_pct` 値）にフォールバックします。

折れ線チャート上には JILS 2021 物流コスト調査の **業種別平均線** が破線で重なります（製造業 1.8% / 卸 4.8% / 小売 3.1% / 連鎖化 3.5%）。経営会議で「業界平均より X% 高い／低い」を一目で説明できます。

悪化判定は固定 pp ではなく **baseline 比 相対率** を使います。業種別水準（1.8〜4.8%）の差を吸収し、製造業・卸売業のどちらでも公平に「悪化中」を検出するためです。

この画面は月次会議で「先月から何が悪化したか」を 30 秒で説明するために設計されています。経営会議に出すときは、悪化アラートの message 文をそのまま貼れる構造になっています。

### 4.11 荷待ちヒートマップ

| 項目 | 内容 |
|------|------|
| URL | `/dashboard/wait-heatmap` |
| 何をする画面か | 拠点別・時間帯別に荷待ち時間を可視化し、重点改善対象を見つける |
| 主な入力 | 会社 ID、またはサンプル企業 |
| 主な出力 | 拠点 x 時間帯のヒートマップ、平均待機時間、最大待機時間、計測便数、信頼度警告 |

画面の読み方は次の通りです。

| 表示 | 意味 |
|------|------|

### 4.13 業界ベンチマーク

| 項目 | 内容 |
|------|------|
| URL | `/dashboard/benchmark` |
| 何をする画面か | JSIC 業種、都道府県、売上規模、物流コストをもとに、自社の位置づけを見る |

### 4.14 ドライバー需給ギャップ

| 項目 | 内容 |
|------|------|
| URL | `/dashboard/driver-gap` |
| 何をする画面か | 都道府県別に、改善基準告示や2030年試算を踏まえたドライバー不足感を見る |

## 5. 目的別のおすすめ画面

### 5.1 「何から始めればよいか」がわからない

| まず見る画面 | 理由 |
|--------------|------|
| 業種別 CLO 標準パッケージ | 自社の業種で標準的に何を見るべきかがわかる |
| F2 標準化スコア | 足りない KPI と施策が具体的に見える |
| J2 罠スコア | 既に動かしている施策のうち「効いていない」ものが見える |
| 自社プロフィール入力 | 実データを入れる準備ができる |

迷ったら、最初に業種別パッケージを見てください。標準型が見えると、他の画面の意味が理解しやすくなります。

### 5.2 「社内説明資料を作りたい」

| 使う画面 | 理由 |
|----------|------|
| 業界ベンチマーク | 自社の位置づけを説明できる |
| 施策評価 | なぜその施策を選ぶのか、なぜ他は選ばないのかを judgment trail で説明できる |
| シナリオ試算 | 費用対効果とリスクを説明できる |
| 計画書生成 | PPT、Word、Excel、HTML として出力できる |

### 5.3 「現場改善の重点拠点を見つけたい」

| 使う画面 | 理由 |
|----------|------|
| 自社プロフィール入力 | 拠点・荷待ちデータを登録する |

### 5.4 「提出後の運用を回したい」

|----------|------|

## 7. よくある迷いと答え

### Q1. 最初にどの画面を開けばよいですか？

実務なら「自社プロフィール入力」です。デモや上長説明なら「業種別 CLO 標準パッケージ」から始めると伝わりやすいです。

### Q2. 施策プレイブックと施策評価は何が違いますか？

施策プレイブックは、施策を探す画面です。施策評価は、自社に合う Top 3 を選び、不採用理由まで提示する画面です。

| 画面 | 役割 |
|------|------|
| 施策プレイブック | 候補施策の辞書・検索 |
| 施策評価 | 自社条件に基づく優先順位付け + judgment trail |

### Q3. 業種別パッケージと F2 標準化スコアは何が違いますか？

業種別パッケージは「標準型を見る画面」です。F2 標準化スコアは「自社がその標準型にどれだけ近いかを見る画面」です。

### Q4. F2 標準化スコアと J2 罠スコアは何が違いますか？

F2 は「やるべきことをやれているか（網羅率）」、J2 は「やったことが効いているか（費用対効果）」を見ます。

| 画面 | 見るもの |
|------|----------|
| F2 標準化スコア | 業種標準に対する充足度（未計測 KPI・未採用施策） |
| J2 罠スコア | 実行中施策のうち効果が出ていない罠候補 |

### Q5. 計画書生成だけ使えばよいですか？

最短では使えます。ただし、上長説明で「なぜこの施策なのか」と聞かれるため、施策評価、シナリオ試算、F2 標準化スコアも確認した方が説明しやすくなります。

### Q6. デイリーコックピットは計画書作成前にも使えますか？

使えますが、本来は提出後・運用中の画面です。計画作成段階では、まず業種別パッケージ、F2 標準化スコア、J2 罠スコア、施策評価を見た方が自然です。

### Q7. マクロ概況やドライバーギャップは何に使いますか？

外部環境の説明に使います。「なぜ今、物流改善が必要なのか」「この地域でなぜリスクが高いのか」を補足する材料です。

### Q8. 実データがない場合でも説明できますか？

できます。サンプル企業で画面の流れと出力物は確認できます。ただし、実務判断や提出ドラフトには自社データが必要です。

### Q9. 出力された Word はそのまま提出できますか？

提出前のドラフトです。社内レビュー、最新様式との照合、法務・実務担当者の確認を行ってから提出してください。

### Q10. J2 罠スコアで「データ未登録」と出るのはなぜですか？

施策実行記録（投資額・期待効果・実績効果）が `outputs/measure_runs/<company_id>.json` に永続化されていないためです。MCP ツール `logi_clo_waste_traps` または REST `POST /api/v1/clo/waste-traps/{id}` に `measure_runs` を渡すと永続化されます。

## 8. 上長説明用の短い説明文

このダッシュボードを一言で説明するなら、次の表現が使いやすいです。

> Logi-Intel Dashboard は、CLO 対応を「様式を埋める作業」で終わらせず、自社データ、業種別標準、施策評価、シナリオ試算、成果物生成、提出後の運用までつなげる社内向け意思決定支援ツールです。

もう少し短く言うなら、次の説明です。

> CLO が、何を見て、どの施策を選び、どう社内に説明し、提出後にどう運用するかを支援するダッシュボードです。
