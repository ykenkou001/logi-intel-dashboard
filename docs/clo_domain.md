# CLO 業務ドメイン知識

**責任範囲**: CLO（物流統括管理者）の法的定義・業務内容・このプロジェクトとの関連。CLO 支援機能（フェーズ3）を実装する際の必読ドキュメント。

---

## CLO とは

2026 年 4 月から、年間取扱貨物 **9 万トン以上** の特定荷主企業に選任義務化される「物流統括管理者」（Chief Logistics Officer）。

根拠法: 物資の流通の効率化に関する法律（改正物流効率化法）

---

## CLO の主要業務

1. **中長期計画の策定・提出**（初回 2026 年 10 月末）
2. **荷待ち・荷役時間の削減**
3. **積載率の向上**
4. **トラックドライバー負荷の低減**
5. **定期報告**（荷待ち・荷役時間）

---

## 罰則

| 違反内容 | 罰則 |
|--------|------|
| 未選任 | 100 万円以下の罰金 |
| 届出怠慢 | 20 万円以下の過料 |
| 計画未達 | 勧告・命令・企業名公表 |

---

## このプロジェクトとの関連

CLO が中長期計画を策定するために必要な「外部環境データ」を提供する。

| 提供データ | 活用シーン |
|-----------|----------|
| 業界ベンチマーク | 自社の積載率・荷待ち時間が業界平均と比較してどうか |
| 地域別ドライバー需給ギャップ | 採用難易度・賃金水準の根拠 |
| モーダルシフト・共同配送ポテンシャル | 計画の施策立案 |
| 燃料価格・補助金動向 | コスト試算の前提条件 |

## フェーズ 3 実装設計

### 1. 業界ベンチマーク分析（`logi_analyze_benchmark`）

**何を計算するか**: 指定都道府県の運輸業規模を全国と比較してランク化する

| 指標 | 計算方法 | データソース |
|------|---------|------------|
| 全国ランク（1〜47位） | 47都道府県の事業所数を並べて順位付け | e-Stat 0004005642 × 47都道府県 |
| 全国シェア（%） | 当該都道府県 ÷ 全国合計 × 100 | 同上 |
| 隣接ブロック比較 | 同一地方ブロック内での順位（例: 関東6都県内） | 同上 |

**実装上の注意**:
- e-Stat `getStatsData` を47回叩くと過剰アクセス → `cdArea` 未指定で全国一括取得して Python 側でフィルタ
- キャッシュキー: `benchmark:transport:v1`（TTL: 24時間）

---

### 2. ドライバー需給ギャップ推計（`logi_analyze_driver_gap`）

**何を計算するか**: 2024年問題（960時間上限）による実質稼働力の減少幅を都道府県別に推計する

#### 計算式

```
需給ギャップ = 現在の実効稼働力 − 規制適用後の実効稼働力
            = ドライバー数 × (1 − 規制削減係数)
規制削減係数 ≈ 0.13〜0.14（業界団体推計: 年間残業960h上限で約13〜14%の実稼働時間減）
```

#### データソース

| データ | statsDataId | 備考 |
|--------|------------|------|
| 道路貨物運送業 就業者数（都道府県別）| 要探索（国勢調査 2020） | 職業: 輸送・機械運転従事者 大分類 |
| ドライバー平均賃金（道路貨物運送業） | 00600310（賃金構造基本統計） | 全国値のみで可 |

**探索が必要**: 国勢調査の statsDataId は `logi_estat_search` で「輸送 就業者 都道府県」を検索して特定する（実装前に要確認ステップあり）

### 3. 中長期計画ドラフト生成プロンプト（`clo_plan_draft`）

**何をするか**: FastMCP の `@mcp.prompt()` として登録するプロンプトテンプレート。新たなデータ取得実装は不要で、既存ツールを組み合わせるだけ。

```
Claude が自動でやること:
1. logi_macro_overview(prefecture_name) → 外部環境データ収集
2. logi_analyze_benchmark(prefecture_name) → 業界内ポジション把握
3. logi_analyze_driver_gap(prefecture_name) → 2024年問題の影響試算
4. 上記データを使って3ヶ年中長期計画骨子をドラフト
```

**計画書の構成（法定様式イメージ）**:
1. 外部環境分析（マクロ概況）
2. 自社ポジション（ベンチマーク）
3. ドライバー確保・育成計画（需給ギャップ対策）
4. 荷待ち・積載率改善目標（数値目標）
5. 実行スケジュール（3ヶ年）

**実装条件**: `logi_analyze_benchmark` と `logi_analyze_driver_gap` が完成してから着手する

---

### 4. 燃料価格動向分析（後回し）

**課題**: gogo.gs は「今日の価格」1点のみ。時系列分析には蓄積データが必要。

**方針**: 
- MCPサーバー起動のたびに価格履歴を SQLite の別テーブル `fuel_price_history` に自動追記する
- 数ヶ月蓄積後に傾向分析ツールを実装する
- 補助金データは経済産業省の補助金情報ページ（スクレイピング）を検討するが優先度低

**実装順序**: ベンチマーク・需給ギャップより後回し

---

### フェーズ 3 実装順序

```
Step 1: e-Stat 全国一括取得 → 業界ベンチマーク（core/analytics/benchmark.py）
Step 2: 国勢調査 statsDataId 探索 → ドライバー需給ギャップ（core/analytics/driver_gap.py）
Step 3: MCPツール登録（mcp_server/tools/analyze_tools.py）
Step 4: 燃料価格履歴蓄積ロジック追加（core/clients/energy.py）
Step 5: CLO計画プロンプト（mcp_server/prompts/clo_plan_draft.py）
```

### 実装保留（データ待ち）

- 国税庁法人番号: applicationID 取得後（申請済み・約1ヶ月待ち）。取得後は `.env` の `CORP_NUMBER_APP_ID=` に設定するだけで有効化
- 燃料価格動向: 数ヶ月の蓄積後
