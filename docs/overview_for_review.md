# Logi-Intel Dashboard — 社内レビュー説明資料

> **対象読者**: 営業・企画・経営層（エンジニア向けではありません）
> **目的**: 上長・上層部へアプリケーションの狙い、できること、現在地を説明するための理解資料
> **最終更新**: 2026-05-06

---

## 1. 一言で言うと

**「CLO（物流統括管理者）が、社内説明・上長レビューで説明できる物流改善計画を、根拠データ付きで作り、提出後の運用まで追えるようにする社内向け意思決定支援ツール」**

このアプリは単なるダッシュボードではありません。CLO担当者が次の3つを自分で進められるようにするための道具です。

| できること | 意味 |
|------------|------|
| 現状把握 | 自社の物流KPI、業界平均との差、法令上の区分を把握する |
| 意思決定 | どの施策を優先すべきか、効果・実現可能性・法令適合で判断する |
| 成果物作成 | 社内説明用PPT、国交省提出用Word、数値確認用Excelを出力する |
| 運用管理 | 提出後も、今日見るべき未達KPIや放置リスクを3件に絞って確認する |

---

## 2. なぜ作ったか

### 法律対応だけではなく、経営判断が必要になる

2024年4月からトラックドライバーの時間外労働上限規制が始まり、いわゆる「物流2024年問題」が本格化しました。これにより、荷主企業にも物流改善の責任が求められています。

2026年4月からは、一定規模以上の荷主企業に対して次の対応が必要になります。

| 対応 | 内容 |
|------|------|
| CLO選任 | 物流統括管理者を選任する |
| 中長期計画 | 初回は2026年10月末までに提出 |
| 定期報告 | 毎年7月末に実績を報告 |
| 改善活動 | 荷待ち、荷役等時間、積載率などを継続改善 |

問題は、CLO担当者が「様式を埋める」だけでは足りないことです。経営層からは、なぜその施策なのか、投資に見合うのか、法令上のリスクは何かを説明する必要があります。

### CLO担当者の現実的な困りごと

| 困りごと | 実態 |
|----------|------|
| 何から着手すればよいかわからない | 国交省様式はあるが、自社の数値・施策・根拠の作り方が難しい |
| 社内調整で説明しにくい | 「積載率を上げます」だけでは投資判断に足りない |
| 業界標準が見えない | 自社が製造、卸、小売、連鎖化のどの標準から外れているか判断しづらい |
| 施策が形骸化しやすい | やったことになっているが、効果が出ていない施策を見逃す |
| コンサル依存になる | 数百万円規模になりやすく、社内で説明力が残りにくい |

このアプリの狙いは、CLO担当者の机に常駐する「計画策定と運用の補助担当」を作ることです。

## 3. アプリの全体像

現在の Logi-Intel Dashboard は、次の4領域でCLO業務を支援します。

```
1. データ取得・現状把握
   e-Stat、気象庁、xROAD、燃料価格、自社Excelを統合

2. CLO計画策定
   ベンチマーク、適用判定、目標提案、施策評価、シナリオ試算

3. 成果物生成
   社内説明PPT、様式第3 Word、Excel、Markdown、定期報告書ドラフト

4. 継続運用・標準化
   デイリーコックピット、業種別標準パッケージ、F2標準化スコア、J2罠スコア
```

以前の資料では、主に「計画書を作る」部分が中心でした。現在はそれに加えて、提出後の運用、業種別の標準化、施策が効いていない状態の検出まで広がっています。

## 4. 利用シーン別に見る主な機能

### A. まず現状を知る

| 機能 | 何がわかるか |
|------|--------------|
| 都道府県マクロ概況 | 地域の物流環境、燃料価格、気象リスク |
| 業界ベンチマーク | 自社の売上規模、物流コスト比率、業界平均との差 |
| ドライバー需給ギャップ | 改善基準告示や2030年試算を踏まえた地域別不足感 |
| 適用判定 | 特定第一種荷主、第二種荷主、連鎖化事業者に該当するか |
| 自社データ入力 | Excelテンプレートから拠点、荷待ち、荷役、KPI履歴を取り込む |

使用データは、e-Stat、改善基準告示、物流分野の国の目標値、業界ベンチマーク、サンプル企業データなどです。RESAS API は2025年3月24日に終了しているため、現行の設計では新規利用しません。

### B. どの施策をやるべきか決める

アプリは10種類の標準施策を持ち、会社の状況に合わせて優先順位を出します。

| 施策例 | 主な目的 |
|--------|----------|
| モーダルシフト | 長距離輸送のCO2・人手負担を下げる |
| TMS配車最適化 | 積載率と配送効率を上げる |
| 共同配送 | 複数社・複数拠点の配送を束ねる |
| バース予約 | 荷待ち時間を削減する |
| パレット標準化 | 荷役等時間を削減する |
| 中継輸送 | 長距離運行の拘束時間を抑える |
| WMS導入 | 倉庫側の作業効率を上げる |

施策は、ROI、実装可能性、法令適合、補助金・認定制度との相性などで評価されます。単に「効果が大きそう」ではなく、「この会社で本当に実行できるか」も見ます。

#### 施策評価Top3の読み方

施策評価画面のTop3は、「この会社で最初に検討するなら、この3施策が比較的優先度が高い」という候補リストです。確定した実行計画ではなく、社内調整のたたき台として使います。

| 表示項目 | 意味 |
|----------|------|
| 総合 89.0/100 | 4軸を重み付けした総合点。高いほど優先候補 |
| ROI | 投資額に対して、年間コスト削減がどれくらい見込めるか |
| 実装可能性 | 難易度と、自社に必要リソースがあるかを見た点数 |
| 法令適合 | 様式第3の必須項目や関連条文にどれだけ直接つながるか |
| 補助金 | 使えそうな補助金・支援制度があるか |
| 期待効果 | 年間コスト削減、CO2削減、回収期間の概算 |
| 主管部門 | 主にどの部門が進める想定か |
| 想定月次KPI | 実行後に毎月追うべき指標 |
| 依存関係 | 先に社内合意やシステム導入が必要なもの |
| 選定根拠 | なぜ候補に上がったかの説明文 |
| 他施策との比較 | Top3内、または不採用候補との差分 |

たとえば `パレット標準化` が1位に出る場合、「投資回収が早く、法定様式にも書きやすく、現場で始めやすい」という意味です。一方で、`中継輸送` が不採用候補に出る場合は、「長距離運行を分割する施策として有効な場面はあるが、このサンプル企業では必要リソースや効果の面で優先度が下がる」という読み方になります。

### C. 社内説明・上長レビューに出せる成果物を作る

計画策定結果から、次のファイルを生成できます。

| 成果物 | 用途 |
|--------|------|
| PowerPoint | 社内説明、上長レビュー、関係部署との調整 |
| Word | 国交省様式第3別紙の中長期計画書ドラフト |
| Excel | 数値表、シナリオ、出典一覧、社内BI連携 |
| Markdown | 担当者がレビュー・修正しやすいテキスト版 |
| 定期報告書ドラフト | 毎年7月末提出に向けた様式第5の下書き |

すべての数値に出典を付ける設計です。社内説明や上長レビューで「この数字はどこから来たのか」と聞かれたときに説明できることを重視しています。

### D. 提出後も運用する

現在の最新版では、計画を作って終わりではなく、提出後の運用支援も入っています。

| 機能 | 説明 |
|------|------|
| デイリーコックピット | CLOが朝見るべき「今日の3判断」を表示 |
| 意思決定ログ | 採用、保留、却下の判断を記録 |
| 拠点別荷待ちヒートマップ | 拠点と時間帯ごとの待機リスクを可視化 |
| F2標準化スコア | 業種別標準パッケージにどれだけ準拠しているかを0-100で評価 |
| J2罠スコア | やっているのに効果が出ていない施策を検出 |

特にデイリーコックピットは、「全部のKPIを見る」のではなく、CLOが今日判断すべきものを3件に絞ります。緊急度、経営インパクト、自信度、想定反論まで含めて表示するため、会議前の確認に使えます。

## 5. 最新アップデートで増えた重要機能

### 1. 業種別 CLO 標準パッケージ

製造、卸売、小売、連鎖化事業者の4業種について、標準的に見るべきKPI、施策、会議体、レポート、データ項目をパッケージ化しました。

| 業種 | 使い方 |
|------|--------|
| 製造 | 工場・出荷拠点を起点に、積載率、荷待ち、共同配送、モーダルシフトを評価 |
| 卸売 | 倉庫・配送網を起点に、共同配送、倉庫DX、物流コスト比率を評価 |
| 小売 | 店舗配送・DCを起点に、納品頻度、待機時間、店舗側制約を評価 |
| 連鎖化事業者 | フランチャイズ本部として、第65条関係の様式に合うKPIと施策に限定 |

個社差分は Override として別管理します。標準から外れていること自体を悪とせず、「合理的な個別最適」なのか「放置された逸脱」なのかを分けて扱います。

### 2. F2標準化スコア

F2標準化スコアは、自社が業種別標準パッケージにどれだけ準拠しているかを0-100で出す指標です。

| 見る観点 | 内容 |
|----------|------|
| KPI充足 | 標準で見るべきKPIを計測できているか |
| 施策充足 | 標準で採用すべき施策が抜けていないか |
| Override分類 | 標準からのズレが承認済みか、未管理の逸脱か |
| 連鎖化ガード | 連鎖化事業者に不適切な荷役等セクション施策が混ざっていないか |

上長向けには、「この会社はCLO運用の標準型からどこが外れているか」を一目で説明するためのスコアと考えると理解しやすいです。

### 3. J2罠スコア

J2罠スコアは、「施策を実施しているのに効果が出ていない」状態を見つけるための機能です。

ただし、開始直後、データ不足、季節要因、外部要因などで誤判定しないように、6つの安全確認を入れています。これにより、現場に対して不当に「効果がない」と決めつけるのではなく、レビュー対象を慎重に絞ります。

### 4. 連鎖化事業者向けの法令ガード

連鎖化事業者は、通常の荷主とは提出様式や条文の扱いが異なります。最新版では、連鎖化パッケージに不適切な荷役等時間短縮セクションや第46条表記が混ざらないよう、コード上で強制チェックしています。

これは、フランチャイズ本部向けの説明や提出資料で条文・様式を取り違えるリスクを下げるための重要な更新です。

## 9. 現時点の注意点

このアプリは機能面ではかなり進んでいますが、上長説明では次の注意点も正直に伝えた方が安全です。

| 注意点 | 説明 |
|--------|------|
| デモ環境である | 本格導入にはセキュリティレビュー、権限設計、運用ルールが必要 |
| 自社データ品質に依存する | 荷待ち、荷役、KPI履歴が入らないと精度は上がらない |
| 出力はドラフト | 国への提出前には人間のレビューと社内承認が必要 |
| e-Stat APIキー確認が残る | Lambda上での一部実データ取得は追加確認が必要 |
| 交通量データはダッシュボード未表示 | xROAD/JARTICの5分値を取得するMCPツールはあるが、Webダッシュボード上で確認する専用画面は未実装 |
| PPTの視覚化強化余地 | 現在も出力できるが、グラフ・図表の表現は改善余地がある |

## 10. よくありそうな質問

**Q. これはコンサルの代替ですか？**

完全な代替ではありません。ただし、コンサルが最初に行う「現状把握、業界標準との比較、施策候補の整理、説明資料のたたき台作成」はかなり置き換えられます。社内で自走するための道具と考えるのが現実的です。

**Q. 何が一番の差別化ですか？**

単に計画書を生成するだけでなく、業種別標準パッケージ、F2標準化スコア、J2罠スコア、デイリーコックピットまで持っている点です。つまり「一度作って終わり」ではなく、CLOの継続運用に踏み込んでいます。

**Q. 数値は信頼できますか？**

政府統計、省庁資料、改善基準告示、物流分野の目標値、JILS等の業界ベンチマークを根拠として扱います。出力には出典を付ける設計です。ただし、自社入力データの品質が低い場合は、結果の精度も下がります。

**Q. 交通量はわかりますか？**

Webダッシュボード上では確認できません。JARTIC/xROADの道路交通量APIから、常時観測点コードまたは狭い地理範囲を指定して5分値の上下線別交通量を取得するMCPツールはありますが、現時点ではダッシュボード画面には組み込まれていません。都道府県全体の交通量を自動集計したり、施策評価Top3の点数に直接反映したりする機能でもありません。

**Q. 施策評価Top3はどう読めばよいですか？**

Top3は「今すぐ実行決定すべき3施策」ではなく、「社内調整で優先的に検討する3施策」です。総合点は、ROI 35%、実装可能性 30%、法令適合 25%、補助金 10% の重みで計算しています。ROIは費用対効果、実装可能性は社内リソースと難易度、法令適合は様式第3に書きやすいか、補助金は支援制度の有無を見ます。画面に出る「期待効果」「主管部門」「月次KPI」「依存関係」は、社内で誰が何を確認すべきかを整理するための補助情報です。

**Q. 自社データを入れても大丈夫ですか？**

現在はAWS東京リージョンのPoC環境です。本格導入時は、入力データの機密性、アクセス権限、保存期間、監査ログを別途設計する必要があります。ローカル実行も可能です。

**Q. 2026年10月末の初回提出に間に合いますか？**

アプリの主要機能は揃っています。実務上は、自社データをExcelテンプレートに入れ、生成されたドラフトをCLO担当者と関係部署がレビューし、社内承認を通す時間が必要です。数週間で初回ドラフトを作る使い方が現実的です。

**Q. どの会社に向いていますか？**

製造、卸売、小売、連鎖化事業者に特に向いています。業種別パッケージが用意されているため、CLO運用の標準型から説明を始められます。
